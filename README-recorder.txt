After stream ends → remove voice → split → send to Drive (v6.36): Recorder Settings has a global toggle "After stream ends: remove voice → split → send to Drive" and each streamer has a "→ Drive" switch (both default on, stored in the same twitch-auto-recorder-v4 key; the helper also keeps them in ~/TwitchRecordings/.drive-pipeline.json so it works with the page closed). Only when a recording finalizes (Stop, stream ended, or mid-resume give-up — never the growing file) the helper queues one Music-only job for the whole session on the shared one-at-a-time Demucs queue: every segment is cut into ~10-minute FLAC chunks, run through Demucs, joined and encoded to <first segment>-music.ogg (Vorbis q6, 44.1 kHz stereo; an existing -music is reused for single-segment sessions). It waits while disk space is low. The full -music.ogg is kept; it is then cut with -c copy into equal parts: count = ceil(size / 45 MB), but parts are never shorter than 10 minutes unless that would push a part to 50 MB or more (then re-cut with one more part). If Google Drive for Desktop is found they are copied (temp file + rename) into the Drive target: your chosen folder (Convert → Google Drive → Auto-send → "Use this folder"), else a My Drive folder named "Twitch" / "TwitchRecordings" / "Twitch Recordings", else My Drive/Twitch Recordings/Music only (created). History rows show a ☁ Sent / ⏳ Waiting / ⚠ failed badge, "Send to Drive now" and "Split for Drive" (works on any existing -music file). Browser notifications fire when parts are ready or sent. API: GET /api/pipeline/status, POST /api/pipeline/prefs {enabled, users, target}, POST /api/pipeline/split {name}, POST /api/pipeline/deliver {base?}; /api/record accepts afterStream. While the pipeline is on for a streamer, the browser's per-segment Auto Music only is skipped for that streamer (the helper does the whole session). The helper never restarts while a recording, a Demucs job or a Drive copy is active. macOS note: the helper runs as a background LaunchAgent, so macOS privacy can block it from the Google Drive folder ("Operation not permitted"); the job then shows the fix — System Settings → Privacy & Security → Full Disk Access → add the helper's python3 — and retries every 5 min.
Free local Drive parts after successful send (v6.37): After a delivery reaches status=sent (all parts copied into the Drive target), the helper removes ~/TwitchRecordings/Drive parts/<base>/ and logs bytes freed — the full -music.ogg in ~/TwitchRecordings is kept. Waiting / error / FDA-blocked deliveries keep local parts so retry and Send to Drive now still work. Re-split for Drive can recreate parts anytime. History Delete (and Delete selected) with withSiblings also removes matching Drive parts/<native_stem>/; deleting a -music primary removes Drive parts/<music_base_stem>/ and counts those bytes in bytesFreed. Actively sending deliveries refuse delete with HTTP 409 for that base; removing parts for a waiting delivery drops that delivery entry so the UI does not claim parts are ready.
Send the original to Drive too (v6.38): Recorder Settings has "Send original to Drive" and each streamer has an "Original → Drive" switch (both default on; same twitch-auto-recorder-v4 key; also stored in ~/TwitchRecordings/.drive-pipeline.json). The local original in ~/TwitchRecordings is never deleted or moved by the pipeline; the v6.37 cleanup only removes Drive parts/<base>/ after a successful parts send. No clobbering between computers (Mac + Windows backup): if Drive already has a file with the same name and size it counts as sent and is not copied again; if the name exists with a different size, this computer's copy is saved as <name>-<ComputerName>.ext instead of replacing it (same rule for parts, except a manual Re-split from this computer may replace its own parts). Unmute add-on — auto-unmute Twitch on Arm (v6.31)
-------------------------------------------------
Twitch often autoplay-mutes the player, which makes tab-capture audio silent. The recorder page cannot touch other tabs, so v6.31 ships a small Chrome (MV3) extension, "Twitch Auto-Recorder Unmute" (repo folder extension/, installed/packaged as twitch-unmute-extension).
When you click Arm (before and after the tab picker), and when the silence watchdog fires for an armed streamer (once per silence episode), the page asks the add-on to unmute that streamer. The add-on finds open tabs at twitch.tv/<username> (www./m., popout twitch.tv/popout/<username>/player, or player.twitch.tv/?channel=<username>; case-insensitive, query/hash ignored), clears Chrome's tab-level mute, and on the page: clicks Twitch's mute button when it shows "Unmute", sets the <video> unmuted, and raises volume 0 → 50%. It retries for ~10s while the player loads. You'll see "🔊 Unmuted Twitch for <name>". The recorder's own hidden keepalive <video> stays muted on purpose.

Install (Chrome / Edge / Brave):
  1) Get the folder: Mac installs put it at ~/Library/Application Support/TwitchRecorder/twitch-unmute-extension (install.sh copies it there), or unzip twitch-unmute-extension.zip, or use extension/ from the repo.
  2) Open chrome://extensions
  3) Turn on Developer mode (top-right toggle)
  4) Click "Load unpacked" and pick the twitch-unmute-extension folder
  5) Reload the recorder page (GitHub Pages or http://127.0.0.1:8765/). If you use the file:// HTML, also enable "Allow access to file URLs" on the add-on's Details page.

Limitations: only tabs whose URL is the streamer's channel page (twitch.tv/<username>) or the popout/player URLs above are matched — raids/host redirects to another channel or /videos pages are not. Chrome may block unmuting a muted-autoplay video without a click (autoplay policy); then the add-on keeps it playing muted and the UI asks you to click the Twitch tab and unmute manually. If the add-on isn't detected, Arm shows a one-time dismissable hint. Manual unmute always still works.
